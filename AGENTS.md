# AGENTS.md

Guidance for AI agents working in this repository.

## What This Is

Terraform provider for Gravitee APIM (API Management). Most code is **generated by Speakeasy** from an OpenAPI spec — do not manually edit files marked with `// Code generated by Speakeasy`. Custom code is preserved within marked regions (e.g., `// BEGIN GRAVITEE CLOUD INIT`).

## Commit messages

CI runs [commitlint](https://github.com/conventional-changelog/commitlint) on **every commit in a PR** (skipped only for `release-*` branches). A later commit cannot fix an earlier message. Reword the bad commit instead.

Config: `commitlint.config.mjs` (extends `@commitlint/config-conventional`). Validate locally with `make lint-commits` (also part of `make lint`).

### Format

```
type(scope)?: subject

optional body, wrapped
```

Allowed types: `feat`, `fix`, `chore`, `ci`, `docs`, `test`, `refactor`, `perf`, `build`, `revert`, `release`.

Hard failures (level 2):

| Rule | Limit |
|------|--------|
| `header-max-length` | 120 characters (subject line) |
| `body-max-line-length` | **100 characters per body line** |
| `footer-max-line-length` | 100 characters per footer line |
| `type-enum` / `type-case` / `type-empty` | type required, lowercase, from the list above |
| `subject-empty` | subject required |
| `subject-full-stop` | no trailing `.` on the subject |
| `subject-case` | do not use sentence-case, start-case, PascalCase, or UPPER CASE |

Start the subject in lowercase. Optional scope may include a ticket, e.g. `fix(GKO-3100): ...`.

If you include a body, put a blank line after the subject and **wrap every body line at 100 characters**. Do not put the rationale on one long line — that is the usual CI failure.

Good:

```
ci: ignore Speakeasy CLI so prepare-release cannot commit it

mheap/setup-go-cli unpacks the binary into the workspace. git add -A was
staging that 127 MB file, and GitHub rejected the push.
```

Bad (body line longer than 100 characters):

```
ci: ignore Speakeasy CLI so prepare-release cannot commit it

mheap/setup-go-cli unpacks the binary into the workspace; git add -A was staging that 127 MB file and GitHub rejected the push.
```

## Build & Test Commands

```bash
# Build
go build

# Code generation (requires speakeasy CLI)
make speakeasy

# Lint (OAS + Terraform fmt + commitlint)
make lint
make lint-commits      # commit messages on this branch (same rules as CI)
make lint-fix          # fix Terraform formatting

# Sync OAS from upstream APIM
make sync-oas

# Unit tests (no APIM required)
make unit-tests

# Acceptance tests (requires running APIM)
make acceptance-tests

# Example tests (requires running APIM + local provider build)
make examples-tests

# Run a single acceptance test
APIM_USERNAME=admin APIM_PASSWORD=admin APIM_SERVER_URL=http://localhost:30083/automation \
  TF_ACC=1 go test -count=1 -v -run TestAccApiv4Resource ./tests/acceptance

# Run a single unit test
go test -count=1 -v -run TestSomething ./internal/...

# Local Kind cluster for APIM
make start-cluster                          # full mode
APIM_MINIMAL=true make start-cluster        # minimal (faster, management API only)
make stop-cluster
```

## Architecture

### Code Generation Flow
1. OpenAPI spec lives at the repo root: `automation-api-oas.yaml` (synced from upstream APIM via `make sync-oas`)
2. Overlays in `.speakeasy/overlays/` (one file per resource: `apiv4.yaml`, `application.yaml`, `dictionary.yaml`, `group.yaml`, `shared-policy-group.yaml`, `subscription.yaml`, plus `common/`) tweak the spec before generation
3. Speakeasy generates SDK (`internal/sdk/`) and provider code (`internal/provider/`)
4. Config: `.speakeasy/gen.yaml` and `.speakeasy/gen.lock`
5. `make speakeasy` also runs `make doc-gen`, which regenerates `docs/` via `graviteeio/doc-gen` (config in `.docgen/config/`) — never hand-edit files under `docs/`

### Provider Structure (`internal/provider/`)
- **Resources** (6): `apim_apiv4`, `apim_application`, `apim_dictionary`, `apim_group`, `apim_shared_policy_group`, `apim_subscription`
- **Data sources** (6): mirror resources for read-only access
- Each resource has: `*_resource.go` (CRUD), `*_resource_sdk.go` (type mapping)
- `provider.go` — provider config, auth (bearer/cloud/basic), schema
- `utils.go` — HTTP logging, state merging, plan refresh helpers
- `reflect/` and `typeconvert/` — Terraform ↔ SDK type conversion
- `planmodifiers/` — custom plan modification logic per type
- `validators/` — custom validation logic
- `customtypes/` — RFC3339 datetime, trimmed string types

### SDK (`internal/sdk/`)
- Generated Go client, one file per API group: `apis.go`, `applications.go`, `dictionaries.go`, `groups.go`, `sharedpolicygroups.go`, `subscriptions.go` (entrypoint: `graviteeapim.go`)
- Models in `models/operations/` and `models/components/`

### Tests (`tests/`)
- `tests/acceptance/` — resource lifecycle tests (create, read, update, delete, import)
- `tests/examples/` — runs actual Terraform configs from `examples/`
- All acceptance/example tests require a running APIM instance

### Authentication
Provider supports three auth methods (checked in order):
1. Service account token (`APIM_SA_TOKEN`)
2. Gravitee Cloud token (`APIM_CLOUD_TOKEN`)
3. Basic auth (`APIM_USERNAME` / `APIM_PASSWORD`)

## Changing Provider Schema Behavior

**To change provider schema behavior** (plan modifiers, computed fields, validators, defaults, suppress diffs, etc.), add or update entries in `.speakeasy/overlays/` and regenerate with `make speakeasy`. Never edit generated files directly.

Key Speakeasy overlay annotations:
- `x-speakeasy-param-computed: true` — mark a field as computed
- `x-speakeasy-param-suppress-computed-diff: true` — add `SuppressDiff` plan modifier (only works for Unknown plan values)
- `x-speakeasy-plan-modifiers: MyModifier` — reference a custom plan modifier function from `internal/planmodifiers/<type>planmodifier/`

Custom plan modifiers, validators, and types in `internal/planmodifiers/`, `internal/validators/`, and `internal/customtypes/` are **non-generated** and can be edited freely.

## Key Conventions

- Generated code is the majority of the codebase — custom changes go in marked regions or non-generated files
- Import IDs are JSON-encoded composite keys (see test files for format)
- APIM compatibility: 4.9+
- CI runs acceptance tests across a matrix of Terraform versions (1.9.x, latest) × APIM versions (4.9.x, 4.10.x, 4.11.x, master-latest/4.12.x)
- Issues tracked at github.com/gravitee-io/issues with tag `project: GKO`
- Commit messages must pass commitlint (see **Commit messages** above)
